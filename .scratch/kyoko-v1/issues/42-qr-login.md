## Answer

Merged to main as `40deae0`. Docs: `docs/sign-in.md` ("QR login": handshake, endings table, mock), `docs/testing.md`, `docs/ui.md`, `docs/fingerprint.md`, `docs/parity.md`.

- Protocol (checked against docs.discord.food "Remote Authentication", 2026-10-26): v2 at `wss://remote-auth-gateway.discord.gg/?v=2`, Origin `https://discord.com`, 2048-bit RSA-OAEP/SHA-256 key as base64 SPKI DER in `init`; hello, nonce_proof, pending_remote_init (fingerprint = b64url sha256 of the DER), pending_ticket (`id:disc:avatar:username`), pending_login, cancel; closes 4003 timeout, 1000 done/cancelled, 4001/4002 handshake failure; exchange `POST /users/@me/remote-auth/login {ticket}` → `{encrypted_token}`. The forked handshake in `crates/login/src/qr` already matched; changed: typed endings `QrEvent::Failed(LoginError)`, new `LoginError::Captcha` (no longer every 400), `QrEvent::Code{url}`, `QrEvent::Scanned(Scanner)`, the exchange never retries and sends the web client's REST headers with Referer `https://discord.com/login` (`fingerprint::LOGIN_REFERER`) and no Authorization. QR pixels moved to the desktop (`apps/desktop/src/ui/qr_code.rs`, `qrcode` crate moved from login). Nothing logs the token, ticket, keys or payloads.
- Bridge `crates/bridge/src/qr_login.rs` (`QrSignIn`, UI-free): stages Idle / Waiting / Code / Scanned / SigningIn / Ended(QrEnd: Expired, Cancelled, Captcha, Refused, Rejected, Network, Broken, each with its message); `follow(&Flow)` starts a code when the login screen is up and the notice accepted, stops when it leaves; `refresh` for Refresh and "Not me, start over"; stale codes ignored by generation. Tokens go `Flow::redeem(token)` (= `Gate::check_token` → `Gate::check`) then `Flow::redeemed`, which returns a failure to the QR column; `Gate::qr_config` builds the config from the launch identity and REST base.
- Mockcord `remote_auth.rs`: real RSA handshake at `/remote-auth` (`Server::remote_auth_url`), closes 4001 on a wrong nonce proof and 4003 after `MockConfig::remote_auth_timeout_ms`; exchange route outside the auth guard (injected replies such as captcha apply); `Control::scan_qr_code`, `confirm_qr_login`, `cancel_qr_login`, `expire_qr_code`, `garble_next_qr_nonce`, `qr_codes_shown`, `qr_connections`; a `phone=scan|login|expire` query plays the phone for captures and the headless run.
